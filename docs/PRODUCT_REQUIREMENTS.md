# TabRecord 产品需求文档

- 状态：Draft
- 版本：0.1
- 更新日期：2026-08-27
- 负责人：待定

## 1. 问题与机会

吉他手记录即兴、练习或创作时，通常需要在演奏与手工记谱之间切换。普通音频转 MIDI 只能给出音高和时间，而吉他 TAB 还必须决定弦与品；同一音高存在多个合法位置，纯音频无法唯一确定。现有 Guitar Pro 文件和渲染生态可承担交换与展示，但不会自动解决低延迟转录、版本修订和演奏姿态融合。

TabRecord 要把这几个环节串成一个可校正的实时工作台：

```text
演奏 → 暂定音符 → 节拍/时值 → 弦品候选 → 实时 TAB → 人工修订 → GP8/MIDI
                         ↑
                  手势与可演奏性先验
```

## 2. 目标用户与核心场景

### 2.1 目标用户

- 想快速记录 riff、solo 或和弦进行的吉他手；
- 需要生成可编辑练习材料的教师和学生；
- 研究吉他自动转录、弦品解码或人机协作记谱的开发者。

### 2.2 核心任务

1. 用户选择输入设备、调弦、品数、变调夹和节拍设置。
2. 点击录制后演奏，并在 1–3 秒内看到暂定 TAB。
3. 系统在滚动窗口内修正音高、起止时间、节拍和弦品。
4. 用户点击候选弦品或直接编辑，人工修改立即锁定并进入历史。
5. 用户回放、对齐原音频，导出 GP8 `.gp` 或 `.mid`。
6. 用户导入现有 GP8 文件继续播放、校对或增录轨道。

## 3. 产品原则

- **先承认不确定性**：暂定结果必须可见地标注置信度和状态，不能偷偷改写已确认内容。
- **音频可独立工作**：没有摄像头时仍能输出可用结果；手势只作为可选软先验。
- **本地优先与可恢复**：默认不上传原始音视频；崩溃后可恢复最近会话。
- **可测量**：音符、节拍、弦品、延迟和导出保真度分别测量。
- **GP8 单一边界**：只实现和测试 GP8；先完成输入，再基于同一页面模型完成写回。

## 4. 功能需求

| ID | 需求 | MVP 验收摘要 |
| --- | --- | --- |
| FR-001 | 会话配置 | 支持 6 弦、逐弦 MIDI 音高、0–24 品、变调夹、BPM/拍号；配置进入会话快照 |
| FR-002 | 音频采集 | 选择麦克风；显示输入电平、削波和静音；连续录制 30 分钟不丢失已确认事件 |
| FR-003 | 暂定音符 | 输出 onset、offset、pitch、velocity、confidence 和来源；允许最近窗口撤回/替换 |
| FR-004 | 节拍与量化 | 支持固定 BPM/拍号；自动速度为实验功能；原始时间与量化时间同时保留 |
| FR-005 | 弦品解码 | 每个音符给出合法候选和首选；不生成调弦/品数之外的位置；和弦满足基本可演奏约束 |
| FR-006 | 手势先验 | 完成显式授权和指板校准后，输出弦/品概率；摄像头失败时自动退回音频路径 |
| FR-007 | 实时 TAB | 标准谱/TAB 至少每 100–250 ms 合并一次更新；显示录制头、暂定区和确认线 |
| FR-008 | 人工纠错 | 支持音高、弦、品、起止、时值、删除和锁定；修改可撤销/重做且记录来源 |
| FR-009 | GP8 输入 | 读取 GP8 `.gp` 并映射为可编辑页面；受支持字段、不支持字段和降级结果可检查；这是 GP 兼容的 P0 目标 |
| FR-010 | GP8 写回 | 输入模型稳定后，把当前页面快照写为 GP8 `.gp`；在 Guitar Pro 8 重开后保留支持子集中的音高、节奏、弦品、调弦和拍号 |
| FR-011 | MIDI 导出 | 导出 Type 1 MIDI；保留 tempo、time signature、note on/off、velocity 和 pitch bend（可用时） |
| FR-012 | 回放与同步 | 原音频、MIDI 合成和乐谱光标共享时间轴；用户可循环最近 1/2/4 小节 |
| FR-013 | 会话保存 | 保存原始事件、派生事件、人工修改、配置和兼容版本；媒体可外置引用 |
| FR-014 | 诊断 | 可导出不含原始媒体的诊断包：版本、性能、事件统计、错误和配置 |

## 5. 实时状态模型

每个识别事件必须处于以下状态之一：

- `candidate`：单帧/单窗候选，通常不直接渲染；
- `provisional`：已合并，允许模型在修订窗口内更新；
- `committed`：跨过确认线或由用户确认，模型不可自动改写；
- `locked`：用户编辑/锁定，只有显式操作才能修改；
- `rejected`：保留在审计历史中但不参与乐谱。

默认确认线建议落后录制头 1–2 小节，具体值由延迟与稳定性实验决定。

## 6. 性能与质量要求

### 6.1 延迟预算（MVP 目标）

| 指标 | 目标 |
| --- | --- |
| 音频块从采集到工作线程 p95 | ≤ 50 ms |
| 新 onset 到暂定音符可见 p95 | ≤ 1.5 s |
| onset 到默认确认 p95 | ≤ 3.0 s 或 2 小节，以较晚者为准 |
| 已确认小节到导出模型同步 p95 | ≤ 500 ms |
| 交互期间主线程长任务 | 每分钟不超过 1 个 > 100 ms 的任务 |

这些是产品目标，不是对候选模型的既成能力承诺。技术 spike 必须在参考设备上给出测量结果。

### 6.2 准确度与稳定性

- 分别报告 note onset F1、note-with-offset F1、frame F1、string accuracy、string+fret accuracy 和节拍偏差；
- 所有模型必须与“固定位置动态规划”和 Basic Pitch/TabCNN 类基线比较；
- 加入手势先验后，目标是在多模态测试集上将弦品错误相对降低至少 10%，且音高有效性不下降；
- 被标记为 `committed` 后，后台模型不得更改事件；
- GP8 支持子集的输入与写回测试中，音高、onset、duration、string、fret、tuning、tempo、time signature 应 100% 一致。

### 6.3 可靠性、隐私与可访问性

- 原始音频和视频默认仅保存在本机，摄像头默认关闭；
- 权限被拒绝、设备断开、模型不可用时提供可恢复状态；
- 每 5 秒或每次确认小节后持久化事件增量；
- 键盘可完成录制、停止、撤销、重做、移动音符和选择弦品；
- 不以颜色作为区分暂定/确认状态的唯一方式。

## 7. MVP 与后续版本

### MVP（0.1）

- 浏览器/PWA，本地麦克风；
- 固定 BPM 和标准六弦；
- 音频到音符的近实时适配；
- 可演奏性弦品解码；
- alphaTab 展示与播放；
- GP8 输入、基础编辑、会话恢复与 MIDI 导出；
- GP8 写回在输入模型稳定后完成，仍属于 MVP 验收，但不阻塞第一个垂直切片；
- 手势只做离线/录后验证 spike，不阻塞 MVP。

### Beta（0.2）

- 摄像头校准和手势软先验；
- 自动 tempo/downbeat、连音/弯音等常见技法；
- 低端设备降级策略与更长会话；
- 用户可比较多个弦品解码候选。

### Later

- 吉他/贝斯/尤克里里模板；
- 移动端或桌面壳；
- 多轨、伴奏分离、协作；
- 自定义/微调模型与插件 API。

## 8. 明确不在 MVP 范围

- 完整乐队混音的一键高保真分轨与扒谱；
- Guitar Pro 8 全量字段的无损编辑器替代品；
- 所有技法自动检测；
- 云端账号、分享、商店或版权曲库；
- MIDI 吉他硬件和 DAW 插件；
- 出版级自动排版和零人工修订保证。

## 9. 成功指标

- 10 名目标用户中至少 7 名能在无指导情况下完成“导入或录制 → 修 1 个错误 → 导出 GP8/MIDI”；
- 样例会话 95% 能恢复且不丢失已确认事件；
- 参考设备上达到延迟预算，且 30 分钟录制无音频块丢失；
- 用户校正一个错误的中位操作次数不超过 3 次；
- 每个发布版本公开固定基准集上的准确度、延迟和已知失败模式。
