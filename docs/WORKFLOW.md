# 研发工作流

## 1. 工作项类型

- `epic`：跨多个可交付结果的目标；
- `feature`：用户可观察的行为；
- `bug`：行为偏离已写明的验收条件；
- `spike`：有时限的可行性验证，产出证据和决策；
- `experiment`：有基线、数据、指标和假设的 ML/信号处理实验；
- `chore`：工具、依赖和维护。

不确定的技术承诺先转成 `spike`，并设 timebox。Spike 的完成标准不是“写了代码”，而是回答问题、保存最小复现实验并给出 go/no-go/next-test。

## 2. 看板状态

```text
Inbox → Triaged → Ready → In progress → Review → Validate → Done
                    ↘ Blocked ↗
```

- `Inbox`：未经整理的想法；
- `Triaged`：已明确类型、优先级和负责人候选；
- `Ready`：满足 Ready 定义，可直接开始；
- `Review`：代码/文档评审；
- `Validate`：在基准、真实设备或用户场景验收；
- `Done`：证据已附在任务中并满足完成定义。

WIP 建议：每位开发者同时最多 1 个 `In progress`，全团队最多 2 个无主 `spike`。

## 3. Definition of Ready

一个工作项进入 `Ready` 前需要：

- 说明用户/研究问题和不做的后果；
- 有可验证的验收条件；
- 标明依赖、风险、数据和设备需求；
- 对算法任务定义基线与指标；
- 对媒体数据说明来源、许可证和隐私；
- 能在 1–5 个工作日内完成，否则拆分。

## 4. Definition of Done

- 验收条件全部通过并附证据；
- 相关单元、集成、黄金文件和性能测试通过；
- 未引入未经记录的隐私/许可证风险；
- 文档、ADR、兼容报告或迁移说明已更新；
- 可观察性足以定位失败；
- 已在目标浏览器/参考设备验证；
- 回滚路径明确。

## 5. 双轨节奏

### 5.1 研究轨

```text
假设 → 数据/许可检查 → 基线 → 单变量实验 → 误差分析 → 决策记录
```

每个 experiment 必须记录：

- 数据集名称、版本、切分和许可证；
- 代码 commit、环境 lock、随机种子；
- 输入预处理、模型权重 hash；
- 指标、置信区间或样本数；
- 至少 5 个典型失败例；
- 与产品延迟/内存预算的关系。

### 5.2 产品轨

```text
用户切片 → 契约/ADR → 实现 → 自动测试 → 设备验证 → 演示 → 发布
```

产品轨只能使用已通过研究门或明确标记为实验性的组件。实验能力必须有 feature flag 和音频-only fallback。

## 6. Git 与 PR

- `main` 始终可运行；采用短分支与 squash merge；
- 分支含任务号：`feat/TAB-201-live-capture`；
- 影响公共契约的 PR 必须含 schema 迁移和兼容测试；
- 依赖升级单独 PR，alphaTab/模型 runtime 升级必须跑完整黄金集；
- 不提交数据集、原始录音、视频、未授权 GP 文件或大模型权重。

建议检查：

1. format/lint/typecheck；
2. unit/property tests；
3. GP/MIDI golden round-trip；
4. 离线音频 regression；
5. Web 性能 smoke；
6. license/SBOM；
7. 文档链接。

## 7. 决策机制

以下变更必须新增 ADR：

- 内部事件模型和存储格式；
- 推理在浏览器、本地 sidecar 或云端的边界；
- GP/MIDI/alphaTab 适配策略；
- 模型、数据集或许可证影响商业/分发能力；
- 会话兼容性或隐私默认值。

ADR 状态：`Proposed → Accepted → Superseded/Rejected`。代码与文档链接到 ADR，不在聊天记录中保留唯一决策。

## 8. 发布节奏

- `0.0.x`：技术 spike，可破坏契约；
- `0.1.x`：MVP，内部会话格式开始版本化；
- `0.2.x`：手势 beta 与更稳定的兼容策略；
- 每次发布包含已知失败模式、固定基准结果和数据格式版本；
- 准确度下降、p95 延迟回退超过 10% 或黄金文件差异时阻止发布，除非有书面豁免。

## 9. 每周建议

- 周一：整理 Ready 队列，确定一个用户切片和一个研究假设；
- 周中：15 分钟风险同步，重点看延迟、数据和格式问题；
- 周五：用同一套固定样例演示，更新基准趋势和失败案例库；
- 每两周：复核 MVP 范围，删除不能支持核心场景的工作。
