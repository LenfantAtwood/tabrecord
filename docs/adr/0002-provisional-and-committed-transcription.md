# ADR-0002：实时转录采用暂定/确认两阶段

- 状态：Proposed
- 日期：2026-08-27

## 背景

复音音高模型通常需要未来上下文，重叠窗口也会对同一音符产生不同判断。如果一出现候选就永久写入乐谱，会造成重复音符、闪烁和已完成小节被后台悄悄改写。

## 决策

事件以 `candidate → provisional → committed` 演进；用户编辑的字段进入 `locked`。模型仅能在修订窗口内更新或撤回 provisional 事件。跨过确认线后只允许显式用户操作修改。

## 后果

- UI 必须清楚呈现暂定区与确认线；
- 事件协议要支持 insert/update/retract/commit；
- 会增加状态机复杂度，但能给用户稳定、可解释的结果。
