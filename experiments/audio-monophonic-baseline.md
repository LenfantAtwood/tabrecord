## 假设与验收

传统 YIN 音高估计、短时能量门限和音符分段可以提供一个轻量的单音回退路径，连接上传/麦克风、音符事件与 TAB。当前验收仅针对已知音高和时间的合成单音：保持音高、时间与顺序，识别重新拨弦，静音和宽带噪声不产生音符，并限制计算资源。

对照是合成信号的精确生成参数、静音和固定种子噪声。没有训练集、验证集或测试集随机切分，没有使用模型权重。本实验未运行 Basic Pitch、TabCNN 或 GuitarSet，因此不能替代 TAB-401、TAB-406 或真实吉他评估，也不能据此报告真实音乐的 note/frame/string/fret F1。

## 数据、配置与复现

数据版本为 `synthetic-monophonic-v1`。所有 PCM 由脚本在内存生成，没有外部录音、完整数据集或媒体许可依赖；不提交音频文件。代码沿用仓库的许可策略。

合成拨弦的局部时间为 `t`、时长为 `D`、MIDI 音高为 `m`：

```text
f = 440 × 2^((m − 69) / 12)
e(t) = min(1, t / 0.004, (D − t) / 0.008) × exp(−3t)
x(t) = 0.4 × e(t) × [sin(2πft) + 0.5sin(4πft) + 0.25sin(6πft)]
```

起点和时长四舍五入到采样点，输出为 `Float32Array`。脚本采用 48 kHz，单元测试另覆盖 8、44.1 和 96 kHz。八音旋律使用 MIDI `[40,45,50,55,59,64,76,88]`，每 0.3 秒起音，时长 0.23 秒；重复音使用 MIDI 57、起点 `[0.1,0.43,0.76]`、时长 0.3 秒。两组共 11 个预期音符，按顺序比较音高及起止时间，起止容差均为 40 ms。

噪声种子是 `407`，采用 32 位 LCG：`state = (1664525 × state + 1013904223) mod 2^32`，每个样本为 `(state / 2^32 − 0.5) × 0.4`。静音和噪声各 1 秒。全部 PCM 的 SHA-256 保存在结果 JSON；字节 hash 对应记录的 Node/CPU 环境。

算法配置固定为：12 kHz 分析采样率、10 ms hop、64 ms 窗口、YIN 阈值 0.15、最低置信度 0.8、默认 MIDI 40–88、最短音符 80 ms、最长输入 120 秒。分析前做面积平均降采样和全段 DC 均值去除；静音门限为 `max(0.0002, peakRms × 0.015)`。短时同音能量增长用于重新拨弦分段。这些阈值尚未针对真实吉他数据调优。

在仓库根目录运行（Node 24）：

```sh
node --experimental-strip-types experiments/audio-monophonic-baseline.ts
pnpm --filter @tabrecord/web test src/features/audio/transcription.test.ts
```

脚本不依赖第三方包，输出 JSON，任何固定样例或性能样例的内容断言失败都会返回非零退出码。计时不设依赖机器速度的通过阈值。单元测试使用仓库锁定的 Vitest 4.1.11；`pnpm-lock.yaml` 的 hash 也保存在结果中。

本次测量基于 Git HEAD `6dd41e58063f0d2492f97e71e9776bc5ac033b74` 上的未提交工作树；精确实现以源码 SHA-256 `44a4fc012931842f2e07c7a52453a697775a6bca9ec3082973681043bb11c0a8` 为准。脚本输出同时记录源码、脚本、锁文件 hash 和工作树状态，以免将基础提交误当作算法所在提交。

## 合成回归结果

14 项单元测试通过，覆盖以下输入行为：

| 覆盖内容 | 结果 |
| --- | --- |
| 8/44.1/48/96 kHz 的低 E，原始起止时间 | 4 项通过 |
| 六根空弦及高品音 MIDI 76、88 | 通过 |
| 有短暂静音的同音重复、无静音的同音重新拨弦 | 2 项通过 |
| 静音、DC、固定种子宽带噪声；单点 click | 2 项通过 |
| MIDI 36–39、89–96 不折叠进默认吉他音域 | 通过 |
| 二次谐波强于基频；无休止连续换音 | 2 项通过 |
| 录音末尾截断的音符结束时间 | 通过 |
| 无效 PCM/采样率/音域配置及输入时长上限 | 通过 |

独立复现脚本中，八音旋律为 **8/8 正确音高**，三个重复音为 **3/3 正确音高**，没有多余音符；两组起止误差均小于 `1e-12` 秒（浮点运算误差，样例刻意对齐 10 ms 网格）。静音和噪声均为零音符。这不能推导出任意起音时刻具有相同误差。

## CPU 性能烟测

环境：Apple M1、arm64、Darwin 24.2.0、Node v24.19.0。输入为 48 kHz 持续 E2，加上振幅 0.5、0.25 的二次和三次谐波；总增益 0.4，不使用衰减包络或静音，因此全部分析帧保持有声。每种时长预热 1 次，测量 7 次，只计 `transcribeAudio` 调用。

| 输入时长 | 7 次运行耗时，按运行顺序（ms） | p50（ms） | 经验 p95（ms） |
| --- | --- | ---: | ---: |
| 2 秒 | 18.52, 18.46, 18.41, 18.37, 18.39, 18.43, 18.88 | 18.43 | 18.88 |
| 120 秒 | 1181.35, 1131.80, 1120.68, 1125.99, 1113.49, 1112.12, 1102.24 | 1120.68 | 1181.35 |

两种输入均输出一个 E2 音符，完整保持从 0 到录音末尾的时间。分位数使用 nearest rank；7 次运行的 p95 就是最大值，样本量不足以代表稳定的线上 p95。上述数字没有包含解码、Worker 消息、采集、界面更新和 TAB 渲染，也不是参考浏览器的端到端延迟。没有测量峰值内存、物理麦克风丢块或 30 分钟 soak test。

## 浏览器链路检查

同次开发会话在 Codex IAB 内完成上传链路检查，浏览器引擎版本不可见。输入为临时生成的 5 秒、48 kHz、PCM16、mono WAV，SHA-256 为 `e384a9e10b55413ee4e3654e7d6ad194147d99945668c4724a993be11e03d288`。其音高为 `[40,45,50,55,59,64]`，起点为 `[0.25,1,1.75,2.5,3.25,4]`，每个音符 0.5 秒；谐波权重为 `[1,0.3,0.1]`，增益 0.4，包络为 `min(1,t/0.008,(D−t)/0.015) × exp(−1.5t)`。

页面显示 **6/6 正确音高**，起止时间与预期一致到两位小数；alphaTab 显示标准谱和 TAB。将最后一音从二弦五品改为一弦空弦，界面同步更新并显示锁定。页面显示单次推理约 0.04 秒，此读数不是延迟分布。

另用 110 Hz `AudioContext` oscillator 替代 `getUserMedia` 音源，通过实际 AudioWorklet 和录音 UI 完成合成麦克风链路检查。未使用物理麦克风，因此不据此声明设备兼容性、权限恢复、真实录音准确率或丢块性能。文件下载落盘不在本段已验证结论内。

## 尚未验证的失败类型与下一步

以下是算法结构决定的风险假设，尚未使用真实录音形成失败率或回归样例：

| 输入类型 | 可能表现 | 下一轮验证 |
| --- | --- | --- |
| 和弦、扫弦、带伴奏或完整混音 | 单一周期估计丢音或选错基频 | 固定许可的复音样例，与 Basic Pitch 比较 |
| 强失真、弱基频、自然/人工泛音 | 八度错误；合成强二次谐波测试不能覆盖真实音色 | 干净/失真配对吉他录音与逐音标签 |
| 推弦、滑音、较宽 vibrato | MIDI 取整切碎连续音高，无法表达技法 | 标注连续 cents 曲线与技法边界 |
| 很轻的同音重新拨弦、连奏、短于 80 ms 的速弹 | 能量上升不明显时合并，或被最短时长滤掉 | 多力度/速度重复音、hammer-on/pull-off 样例 |
| 房间混响、噪声门、拾音器底噪、削波 | onset/offset 偏移，漏音或误报 | 不同 SNR、混响与输入增益分层评估 |
| 强高频干扰、极端采样率或非标准调弦 | 简单降采样滤波和默认音域存在适用边界 | 专门的抗混叠、低调弦及设备采样率样例 |

当前结论是可以作为明确标注的单音实验路径供上传和短录音试用；不能据此确认 MVP 的真实吉他准确率、复音能力、持续录制可靠性或端到端性能指标。下一步应补充有来源与许可证的真实单音吉他 fixtures，以及物理麦克风、浏览器版本和低配设备的端到端测量。
